# Security and privacy

The app requests Internet access and permission to install its own updates. It has no login, analytics, ad SDK, microphone/storage/location permission or public update-control receiver. Backups and cleartext traffic are disabled. Search/results remain in memory; preferences and update state are private on-device.

Personalization keeps eight bounded genre scores, at most 64 public-title topic scores and 32 channel scores in private Android preferences. Actual playback time and estimated completion adjust them; seeks, pauses and long observation gaps do not count. Short sessions use the existing eligibility thresholds and modest early-exit reductions. Provider category/conservative words still determine genre; unknown genres can independently train topic/channel scores, including Unicode title words. Raw search queries are neither persisted nor used for learning. Explicit feedback keeps at most 80 dismissed video IDs and 24 excluded channel keys; up to 96 recently offered IDs encourage fresh suggestions without permanently excluding them. Channel IDs are preferred, with bounded normalized names as a fallback. Up to 32 preference-name aliases and 24 exclusion-name aliases connect missing-ID records; known different IDs do not merge through these aliases. Alias names are bounded to 120 characters and the stored profile is capped at 32KiB when read. Name-only identities can be ambiguous. Feedback applies to recommendation shelves; public genre catalogs remain browseable. Reset personalization erases all these interests and feedback, separately from Continue watching. Disabling personalization pauses implicit learning and topic discovery, retaining interests and explicit exclusions.

Home discovery requests at most four sources per coordinator batch: rotating public genre queries and, when enabled and available, one query containing at most two learned public-video topic words. Those words disclose inferred interests to the provider; score values and saved viewing/feedback lists are never uploaded. Topic results have a single 30-card in-memory cache; failed optional topic discovery falls back to genre caches without automatic retry. Player suggestions parse at most 32 related summaries from the existing fetched response, adding no network request, and fall back to local topic/creator matching. Ranking runs on a background dispatcher over bounded candidates, with duplicate/current/completed/dismissed/excluded-channel filtering and creator diversity when alternatives exist. Pause/reset/feedback and playback return rebuild the local mix; refresh rotates sources. There is no recommendation polling timer or background service; network requests are cancelled on exit/stop.

Continue watching separately persists at most 24 unfinished records (validated public video ID, bounded title/channel, position, duration and optional detected or source genre) and 100 recent completed IDs in private, backup-disabled preferences. Started non-live videos with known duration qualify after one second; only actual playback end marks completion. Periodic checkpoints and exit save position. Finished replays stay excluded while their ID remains in the bounded completion list. Clear browsing session erases both lists, independent of genre-score reset. Thumbnail URLs are reconstructed from validated IDs; stream URLs/credentials and search queries are never persisted. Records are not uploaded, though resuming sends the selected public ID as ordinary provider playback does. No database, app server, account, telemetry or external recommender is added.

Browse rows/cards render lazily. Catalog requests are serialized and cancelled on screen exit or app stop. Results are capped at 60 distinct cards per genre across eight genres, extractor cursor caches at 16 opaque pages per catalog instance, thumbnail cache at 16 MiB and thumbnail concurrency at four. Failed pagination preserves existing cards and offers retry. These are local resource bounds, not a promise of provider availability or accuracy of genre classification.

Video traffic uses a restricted YouTube/CDN policy. JavaScript evaluation is denied. Updates use a separate HTTPS client, public-IP DNS checks, no cookies/authentication, an exact repository metadata path and bounded GitHub asset redirects. Providers can see normal request metadata and the network IP address.

Update metadata is capped at 8 KiB and signed with the permanent APK key using SHA-256/RSA. Only higher versions for the same package and compatible Android version are accepted. APKs are capped at 64 MiB, checked against the signed byte count and SHA-256, and checked for the same certificate. Android performs final APK signature verification. Invalid updates leave the installed app in place. Key rotation is not implemented.

Updates check on foreground Home/Settings with a six-hour throttle. Downloads stop when leaving these screens or the app. Automatic updates default on and can be disabled. Android may require permission to install from Aprion TV and/or confirmation. Silent installation depends on Android and the device.

Private signing material, local planning, machine paths, recordings, logs and emulator evidence are excluded from public source. Exports use a reviewed source allowlist and hash manifest. GitHub repository names, usernames and commit identity are public; use GitHub's no-reply commit email if desired.

In 0.3.1-beta, inherited upstream test recordings were sanitised after GitHub identified Google API-key-shaped strings. All six flagged values matched the pinned public upstream files; none appeared in the released 0.3.0 APK. GitHub reported validity unknown. We have no authority to revoke third-party keys. Old public commits/copies may still contain the original recordings; sanitisation is not credential revocation.

GitHub secret scanning and push protection are enabled. Install the local pre-push hook with `git config core.hooksPath .githooks`, and provision the pinned scanner with `./scripts/Run-SecretAudit.ps1 -Install`. Checks run before pushes/source exports and in GitHub Actions. The broader scanner examines nested archives to depth two; exact placeholder exceptions apply only to synthetic test data. Hooks can be bypassed, provider-pattern coverage is finite, and no scanner can guarantee that every secret or software vulnerability is detected. Keep signing material and account tokens in private encrypted storage, use least privilege, and revoke any real credential exposure through its issuing account.

Dependency versions, checksums, licenses and provenance are preserved. A moderate Kotlin Gradle plugin build-cache advisory remains a tooling limitation; output caching and incremental compilation are disabled as mitigation. This is not a claim that all dependencies or devices have passed security qualification.

Update checks first use the exact raw GitHub metadata file, then make at most one attempt to the anonymous GitHub Contents API for the same configured repository, branch and package path when the first request fails. Both routes require HTTPS, public DNS addresses, no metadata redirects, no authentication/cookies, an 8 KiB limit and the existing permanent-key signature checks. Invalid signed metadata never triggers a verification fallback. APK redirects stay restricted to the configured release and approved GitHub asset hosts; requests ask caches to refresh short-lived links, with at most one fresh attempt after HTTP401/403.

Matching cached APKs are verified before reuse. Damaged cache entries are evicted and downloaded once; invalid fresh bytes are never promoted. Local error messages use fixed stage/reason codes, numeric HTTP status, app version, Android API and TV time, plus a safe primary-route failure code when fallback was used. No exception messages, response bodies, signed asset URLs, DNS addresses or certificate details are logged or uploaded. Diagnostic state stays in memory. Installation failures distinguish permission, storage, conflict, cancellation and compatibility; Android's own signature verification remains final. Development/trial builds clearly state they have no production update feed.
