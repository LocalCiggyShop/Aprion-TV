# First publication and updates

The first release is a beta while physical-TV/audio/sync testing remains pending. Do not upload development/trial/test APKs, historical dist bundles or the complete workspace.

1. In VS Code Source Control, stage the eligible files, review the staged diff, commit, then use Publish Branch/Push to the existing [Aprion TV repository](https://github.com/LocalCiggyShop/Aprion-TV). The local origin and long-path support are configured. Local evidence, tools and signing material are excluded; the configured commit email uses GitHub's no-reply format.
2. `release/public-updates.properties` defines the public GitHub owner/repository/branch used by the app. Keep it correct for every release.

   The repository was renamed to `LocalCiggyShop/Aprion-TV` on 13 October 2026. Releases through 0.3.6-beta pin the former repository; 0.3.7-beta uses the new address with the legacy Android package. On 14 October the user authorized changing the installed package to `org.privateview.apriontv`, accepting a separate installation. The new app retains the signing key and protocol, uses its own signed feed, and starts with fresh private app data. Preserve historical releases and `updates/org.privateview.quietscreen.qsu`; do not rewrite legacy signed bytes. Historical baseline inspection may accept the two explicitly known packages and the signed legacy repository URL, while still matching every APK hash/size/package/version/certificate. New candidates must use the Aprion TV package/repository. Publish and verify the new APK before announcing its signed feed. Legacy installations need a manual installation of the new package; their updater cannot change an Android package ID.
3. Create the permanent signing key with `scripts/Release-Key.ps1` (already created on the prepared workstation). Run `scripts/Backup-ReleaseKey.ps1` interactively to make a portable encrypted backup with a passphrase you save privately. Copy the verified `portable-backup.p12` to private offline storage. Losing the key prevents compatible updates. The local Windows-protected password file is not a portable backup. Never upload any signing material.
4. Build/test/lint the unsigned release with strict dependency verification, then sign with `scripts/Sign-Release.ps1`. Inspect the exact signed APK's signature, package/version, permissions and contents and complete a malware scan. Reuse the key and increase versionCode for every update.
5. Run `./scripts/Run-SecretAudit.ps1 -Install` to provision the checksum-pinned scanner and `git config core.hooksPath .githooks` to activate the pre-push checks. Source export also requires both publication checks to pass. GitHub secret scanning and push protection are enabled; the Actions workflow checks every new push. These checks reduce risk but cannot guarantee detection of every secret or software vulnerability.
6. Prepare a fresh source bundle with `scripts/Prepare-PublicSource.ps1 -Label <fresh-label>` in the new tag's bundle. Future renamed releases use Aprion-TV.apk, corresponding-source.zip, source-manifest.json, LICENSE, NOTICE.md, runtime.cdx.json, RELEASE_NOTES.md and SHA256SUMS.txt. Keep test APKs, old trial bundles and local workspace files out of release attachments. Corresponding source must match the APK.
7. Create a GitHub Release for the version tag, attach the signed APK, source ZIP, notices and hashes, and mark it pre-release. Publish only after candidate checks pass.
8. The signed `org.privateview.apriontv.qsu` is already in the upload bundle. After publishing the APK asset, add that file to the repository at `updates/org.privateview.apriontv.qsu` on main (GitHub Add file → Upload files, or copy it locally to that path and commit/push). Preserve its contents and the separate legacy feed. Future metadata is generated by `scripts/Sign-Release.ps1 -Tag <release-tag>`. Publish the APK asset **before** committing the feed. Failed uploads must not become announced updates.
9. Use Downloader on the TV to open the APK's GitHub HTTPS asset URL. Allow installation from Downloader when needed; disable that permission afterward. For later updates allow installation from Aprion TV when asked. The app checks/downloads updates without revisiting the URL; Android can still require confirmation.

Do not submit private tokens or signed URLs to public URL shorteners. A real Downloader installation and app-update round trip are required after hosting is available.

The already published v0.3.3-beta asset retains its original name in the renamed repository:

`https://github.com/LocalCiggyShop/Aprion-TV/releases/download/v0.3.3-beta/QuietScreen.apk`

For later releases, increase app/build.gradle.kts versionCode and versionName, build/test/lint, sign with the same permanent key and a new tag, export matching source, publish assets, then replace the signed feed. Automatic checking/downloading requires the app to be foreground on Home/Settings and the TV to be online. A manual check presents an Install update/Later dialog after verification; Settings → Review update reopens it. Install update opens the one-time Android installation-source permission if needed; afterward eligible devices can install automatically. Other TVs may require a confirmation for each update. No URL revisit is needed.
